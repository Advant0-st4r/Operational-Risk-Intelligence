# Block Completion Rubric

## Purpose

Determine whether a block is actually complete.

---

## Complete

A block is COMPLETE only if all conditions are true.

Note: all the helper functions and logistical structuring of implementing each file are AI-written.
Along with most of the code.

Human aspect shining:

### Artifact

- Deliverable exists.
- Deliverable is saved.
- Deliverable is located in the correct path.

### Verification

- Acceptance criteria checked.
- No known blocking errors remain.
- Output matches block objective.

### State

- Current state updated.
- Decisions recorded.
- Open loops recorded.
- Next action defined.

### Handoff

- Another person can continue work.
- Another LLM can continue work.
- Context restoration requires less than 2 minutes.

---

## Incomplete

A block is INCOMPLETE if any condition is true.

### No Artifact

- Thinking only.
- Discussion only.
- Planning only.
- Research only.

### No Verification

- Deliverable not checked.
- Acceptance criteria missing.
- Completion assumed.

### No Handoff

- State not updated.
- Next action missing.
- Open loops missing.

---

## Completion Formula

COMPLETE =
Artifact Exists
AND
Acceptance Criteria Verified
AND
State Updated
AND
Next Action Defined

Otherwise:

INCOMPLETE

---

## Hard Rule

Never claim completion without proof.
